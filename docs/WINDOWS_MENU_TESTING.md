# Windows Menu Testing

本文档用于验证 Windows 原生菜单和前端编辑器行为是否正确联动。macOS 可按同样步骤做回归测试。

本轮目标包为 Windows `1.9.2`（待构建），不是之前的 `1.9.1`。本轮仅安排 Windows 构建 / 验收；Mac、iOS / iPadOS 与商店上传暂不推进。GitHub Actions 使用 `Release Build` 的 `target=windows-only`，不要选择 `all`，不发布正式 Release。

## 前置条件

1. 启动应用并打开一个 `.md` 或 `.markdown` 文件。
2. 准备一段包含标题、正文、列表、表格和 Front Matter 的 Markdown。
3. 分别在阅读模式、编辑模式、源码模式执行菜单操作。

## 编辑菜单

### 撤销 / 重做

1. 切换到源码模式。
2. 输入一段文字。
3. 点击 `编辑 -> 撤销`，确认刚输入的内容被撤销。
4. 点击 `编辑 -> 重做`，确认内容恢复。
5. 使用 `Ctrl+Z` / `Ctrl+Y` 再测试一次。
6. 切换到编辑模式，重复修改、撤销、重做。
7. 切换到阅读模式，点击撤销 / 重做，应显示“当前模式不支持此操作”，不能报错。

### 剪切 / 复制 / 粘贴 / 全选

1. 源码模式中选中一段文本。
2. 测试 `剪切`、`复制`、`粘贴`、`全选` 菜单。
3. 使用 `Ctrl+X`、`Ctrl+C`、`Ctrl+V`、`Ctrl+A` 验证快捷键。
4. 编辑模式中重复上述测试。
5. 阅读模式中复制和全选可以使用系统选择能力；剪切 / 粘贴应降级提示，不能报错。

### 查找

1. 源码模式中点击 `编辑 -> 查找`。
2. 确认 CodeMirror 搜索面板打开。
3. 输入关键词，确认可定位匹配内容。
4. 阅读模式中点击查找，应弹出简单查找输入框并定位页面内容。
5. 编辑模式第一版不提供专用查找面板，应提示当前模式暂不支持查找，不能报错。

## 视图菜单

### 放大 / 缩小 / 实际大小

1. 点击 `视图 -> 放大`，确认文档区域放大。
2. 连续点击，确认最大约为 200%。
3. 点击 `视图 -> 缩小`，确认文档区域缩小。
4. 连续点击，确认最小约为 50%。
5. 点击 `视图 -> 实际大小`，确认恢复 100%。
6. 确认 Markdown 原文没有变化，保存状态不因缩放改变。

### 全屏

1. 点击 `视图 -> 全屏`。
2. 确认窗口进入全屏。
3. 再次点击或使用系统退出全屏方式，确认可以恢复。
4. 如果系统或权限拒绝，全屏失败应显示错误提示，不能导致白屏或崩溃。

## 模式切换联动

1. 在编辑模式修改内容。
2. 用菜单切换到源码模式，确认内容同步。
3. 在源码模式撤销 / 重做，确认 Store content 同步。
4. 切回阅读模式，确认渲染为最新内容。
5. 等待自动保存，关闭重开确认内容保留。

## 标签页、关闭与无备份保存

1. 文件选择器多选两个 `.md`，确认出现在同一窗口的两个标签中；拖入多个文件也应如此。
2. Windows Explorer 冷启动 / 已启动时双击其他 Markdown，确认加入当前窗口的标签，不创建第二个应用。包含空格、中文、`.markdown`、不同大小写路径都要测。
3. 重复打开同一路径（含标准路径和扩展路径）只激活已有标签，不能重载并覆盖未保存内容。
4. 在 A 编辑模式连续输入后立即切到 B，再回 A，最后几个字必须保留；源码模式重复测试。
5. 在 A 修改、切 B，等待 800ms 自动保存。检查 A、B 原文件，不能串写。保存期间再次修改 A，最终磁盘应是最新内容。
6. 打开、自动保存、菜单 / 工具栏手动保存后，目录不应新增 `.md.bak`；已有 `.bak` 不应被删除或重写。
7. 点击标签的关闭图标或 `文件 -> 关闭文件` / `Ctrl+W`，先保存再关闭标签。最后一个标签关闭后应出现欢迎页和历史文件，点击历史文件可重新打开。
8. 模拟保存失败（例如只读目录），关闭不得丢掉标签或内容，应该保留错误状态；修复权限后重试。
9. 窗口右上角关闭和“退出”应等待所有标签的待保存内容，保存失败不退出。不要把窗口关闭按钮改成无反应。
10. “另存为”不能覆盖另一个已打开标签的内容；另存为完成后该标签使用新路径，不在旧路径继续自动保存。

## 导出名称与 Word 锁文件

1. 打开 `深圳故事.md`，Word 默认名为 `深圳故事.docx`；Excel 纯表格文件默认名对应其原文件名。
2. PDF 使用原文档名作为打印标题建议。分别测试系统“另存为 PDF”和 Microsoft Print to PDF，确认不再沿用应用名；最终名称仍由打印驱动控制。
3. 取消打印后确认应用标题恢复，能继续编辑；完成打印也不显示未验证的“已保存”提示。
4. 在没有打开 Word 的新测试目录导出 DOCX，确认本程序只生成目标 `.docx`；打开 Word 后若出现 `~$...docx`，它是 Word 的占用锁文件，关闭 Word 后再检查，不在占用时强行删除。

## 自动回归

- `npm test`（Node.js 22.6+）：文档隔离、并发保存、失败保留、重复打开、关闭回欢迎页、历史记录和另存为竞态。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib`：跨平台参数、多文件参数、保存 / 导出不额外生成备份或 Word 所有者文件。
- 启动 `npm run dev -- --host 127.0.0.1 --port 5173 --strictPort`，用 Playwright CLI 打开页面，再运行 `run-code --filename tests/desktop-ui.smoke.js`。首次运行前创建 `output/playwright/`；测试使用 `tests/fixtures/desktop-ipc.cjs` 模拟原生边界，不接触真实用户文件。
- 浏览器 UI 回归不是 Windows 原生测试。发布前仍需在 Windows 安装新版确认单实例、原生菜单 / 打印、关闭保存与文件关联。
